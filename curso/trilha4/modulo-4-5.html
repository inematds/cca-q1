💰 Message Batches API e Economia de 50%

A Message Batches API da Anthropic permite enviar multiplas requisicoes em um unico lote para processamento assincrono, com desconto de 50% no preco por token. Em vez de fazer 1000 chamadas individuais para processar 1000 documentos, voce envia um lote com todas as requisicoes e recebe os resultados quando estiverem prontos.

Essa economia e possivel porque a Anthropic pode otimizar o scheduling interno — processando os lotes em horarios de menor demanda. O trade-off e que voce abre mao de latencia garantida: os resultados chegam quando estiverem prontos, dentro de uma janela de ate 24 horas.

💡 Economia em Escala

$100
1000 chamadas individuais (real-time)
$50
1000 chamadas em batch (50% desconto)
2

⏰ Janela de 24 Horas e Sem SLA de Latencia

Resultados de batch sao entregues dentro de uma janela de ate 24 horas. Na pratica, a maioria dos lotes completa em minutos a poucas horas, mas nao ha SLA (Service Level Agreement) de latencia. Isso significa que voce nao pode assumir que os resultados estarao prontos em 10 minutos — eles podem levar 10 minutos ou 10 horas.

Essa incerteza de latencia torna batch inadequado para qualquer cenario que exija resposta rapida: chat interativo, pre-merge checks em CI/CD, alertas em tempo real. Batch e para workloads que podem esperar: processamento noturno de documentos, classificacao de backlog, analise historica.

🚨 Cenarios Inadequados para Batch

  • •Pre-merge checks: Desenvolvedores nao podem esperar horas por feedback de code review
  • •Chat interativo: Usuarios esperam resposta em segundos, nao horas
  • •Alertas em tempo real: Deteccao de fraude precisa de latencia sub-segundo
  • •Workflows agenticos: Cada passo depende do anterior — incompativel com batch
3

🚫 Batch Nao Suporta Multi-Turn Tool Calling

Uma limitacao fundamental da Batch API: cada requisicao no lote e uma chamada unica, sem continuacao. A API nao suporta multi-turn tool calling — ou seja, voce nao pode ter um loop agentico onde Claude chama uma ferramenta, recebe o resultado, e decide o proximo passo. Cada requisicao e single-shot.

Isso significa que workflows agenticos (loop com tool_use iterativo) nao podem ser executados em batch. Batch e ideal para tarefas single-shot: extrair dados de um documento, classificar um texto, gerar um resumo — tarefas que completam em uma unica chamada.

💡 Single-Shot vs Multi-Turn

Compativel com Batch (single-shot)

  • • Extracao de dados com forced tool
  • • Classificacao de documentos
  • • Geracao de resumos
  • • Traducao em massa

Incompativel com Batch (multi-turn)

  • • Agentes com loop de ferramentas
  • • Pesquisa iterativa
  • • Code review com leitura de arquivos
  • • Qualquer workflow com tool_use iterativo
4

🏷️ custom_id para Correlacao de Resultados

Cada requisicao no lote pode incluir um custom_id — um identificador definido por voce que e retornado junto com o resultado. Isso permite correlacionar qual resultado pertence a qual requisicao original, essencial quando voce processa centenas ou milhares de itens.

Na pratica, use o ID do documento, numero de fatura, ou qualquer identificador unico do item como custom_id. Quando os resultados chegam, voce mapeia cada resultado de volta ao documento original usando esse ID, sem depender da ordem (que nao e garantida).

📝 Exemplo de Uso de custom_id

// Requisicao no lote:

{"custom_id": "invoice-2025-001",

 "params": {"model": "claude-sonnet-4-20250514",

  "messages": [...], "tools": [...]}}

// Resultado retornado:

{"custom_id": "invoice-2025-001",

 "result": {"type": "succeeded",

  "message": {...}}}

5

🔄 Reenviar Apenas Itens com Falha

Quando um lote completa, nem todas as requisicoes podem ter sido bem-sucedidas. Algumas podem ter falhado por timeout, erro de API, ou rate limiting. A estrategia correta e reenviar apenas os itens com falha em um novo lote — nao reprocessar o lote inteiro.

O custom_id torna isso simples: ao receber os resultados, filtre aqueles com status "errored" ou "expired", colete seus custom_ids, reconstrua as requisicoes correspondentes, e envie um novo lote apenas com esses itens. Repita ate que todos sejam processados com sucesso ou atinjam um limite de retentativas.

💡 Fluxo de Reenvio Seletivo

1.Envie lote inicial com N requisicoes
2.Receba resultados: M succeeded + K failed
3.Filtre os K itens falhados pelo custom_id
4.Reenvie novo lote apenas com os K itens
5.Repita ate sucesso total ou limite de retentativas
6

⚖️ Quando Usar Batch vs Real-time

A decisao entre Batch e Real-time se resume a uma pergunta: o resultado pode esperar ate 24 horas? Se sim, use Batch para economizar 50%. Se nao, use Real-time apesar do custo maior. A latencia e o fator decisivo, nao o volume — voce pode processar alto volume tanto em batch quanto em real-time (com paralelismo).

📊 Matriz de Decisao

Use Batch (50% economia)

  • •Extracao em massa de documentos historicos
  • •Classificacao de backlog acumulado
  • •Analise de sentimento em avaliacoes
  • •Geracao de resumos noturnos
  • •Traducao de catalogo de produtos

Use Real-time (preco cheio)

  • •Chat com usuario (latencia em segundos)
  • •Pre-merge code review em CI/CD
  • •Agentes com loop de ferramentas
  • •Deteccao de fraude em tempo real
  • •Qualquer cenario interativo
