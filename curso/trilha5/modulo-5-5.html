📊 Acuracia Agregada Mascara Problemas

Um sistema com 97% de acuracia agregada parece excelente — ate voce olhar as categorias individuais. Esse numero pode esconder que o sistema acerta 99.5% dos casos simples (que representam 90% do volume) mas apenas 40% dos casos complexos. A media alta mascara performance abismal onde mais importa.

Esse fenomeno e uma manifestacao do paradoxo de Simpson: metricas agregadas podem mostrar uma tendencia completamente diferente das metricas desagregadas por categoria. Em sistemas agenticos, os 3% de erros podem ser exatamente os casos de maior impacto financeiro ou regulatorio.

💡 Conceito Principal

97% de acuracia agregada pode significar 40% em edge cases criticos. Metricas agregadas criam falsa confianca. Sempre desagregar por categoria, tipo de tarefa e complexidade para revelar a performance real.

📊 Exemplo: 97% Agregado Mascara Problemas

Consultas simples (90% do volume) 99.5%
Casos com excecoes (7% do volume) 78%
Edge cases complexos (3% do volume) 40%
Media ponderada agregada 97%

🎲 Amostragem Aleatoria Estratificada

Stratified random sampling garante que a amostra selecionada para revisao humana represente todas as categorias de tarefa proporcionalmente. Em vez de pegar 100 casos aleatorios (que provavelmente serao 90+ casos simples), voce seleciona uma proporcao minima de cada categoria.

Isso garante que edge cases raros — que sao frequentemente os mais criticos — sejam representados na amostra de revisao. Oversampling deliberado de categorias raras e uma pratica comum para garantir visibilidade nessas areas.

💡 Conceito Principal

Amostragem estratificada garante representacao minima de cada categoria na revisao. Oversampling de edge cases garante visibilidade onde problemas sao mais provaveis e mais impactantes.

Amostragem Aleatoria Simples

  • •100 amostras aleatorias do total
  • •~90 casos simples, ~7 com excecoes, ~3 complexos
  • •Problemas em edge cases invisiveis

Amostragem Estratificada

  • •50 simples + 25 com excecoes + 25 complexos
  • •Oversampling deliberado de categorias raras
  • •Problemas em todas as categorias visiveis

🔢 Scores de Confianca por Campo

Em vez de um unico score de confianca para toda a resposta, field-level confidence scores atribuem um indicador individual a cada campo do output. Isso permite identificar exatamente quais partes da resposta sao confiaveis e quais sao incertas.

Por exemplo, em uma extracao de dados de documento, o agente pode ter 0.98 de confianca no nome da empresa mas apenas 0.65 no valor do contrato (porque o documento estava parcialmente ilegivel). O score global seria 0.82, mas o campo critico (valor) esta muito abaixo do aceitavel.

💡 Conceito Principal

Scores por campo permitem revisao granular focada. O revisor humano olha apenas os campos de baixa confianca, em vez de revisar a resposta inteira. Isso otimiza drasticamente o tempo de revisao.

📄 Exemplo: Extracao com Scores por Campo

empresa: "Acme Corp" 0.98
cnpj: "12.345.678/0001-90" 0.95
data: "2026-01-15" 0.82
valor: "R$ 1.250.000,00" 0.65 ← revisao
4

🔀 Roteamento de Baixa Confianca

O roteamento por confianca cria um sistema hibrido onde o agente processa autonomamente todos os casos de alta confianca e encaminha apenas os casos incertos para revisao humana. Isso maximiza a eficiencia do agente enquanto garante qualidade atraves de oversight seletivo.

O threshold de confianca deve ser configuravel por tipo de campo e criticidade. Campos de alto impacto (valores financeiros, dados pessoais) podem ter thresholds mais altos (0.95+), enquanto campos de baixo risco (descricoes, tags) podem aceitar thresholds menores (0.80+).

💡 Conceito Principal

Campos com score abaixo do threshold sao automaticamente roteados para fila de revisao humana. Thresholds sao configurados por criticidade do campo — valores financeiros exigem confianca maior que campos descritivos.

📍 Fluxo de Roteamento

1

Agente Processa e Atribui Scores

Cada campo recebe confidence score individual

2

Threshold Check por Campo

Compara score vs threshold configurado para aquele tipo de campo

3

Roteamento Seletivo

Campos acima do threshold: aprovados. Abaixo: fila de revisao humana.

5

🔄 Calibracao Continua

Scores de confianca so sao uteis se forem calibrados — isto e, quando o agente diz "95% confianca", deveria realmente acertar ~95% das vezes. Se acerta apenas 70%, os scores estao super-calibrados (overconfident). Se acerta 99%, estao sub-calibrados (underconfident).

A calibracao e feita comparando os scores preditos com os resultados reais da revisao humana. Esse feedback loop continuo ajusta os scores ao longo do tempo, mantendo-os alinhados com a realidade de performance do sistema.

💡 Conceito Principal

Scores descalibrados sao piores que nenhum score — criam falsa confianca. O feedback loop humano corrige → sistema ajusta thresholds → scores melhoram garante calibracao continua.

📊 Calibration Check

Score predito: 0.95 Acuracia real: 0.93 Calibrado
Score predito: 0.90 Acuracia real: 0.70 Overconfident
Score predito: 0.60 Acuracia real: 0.92 Underconfident

🖥️ Design de Interface de Revisao

A interface de revisao humana deve ser otimizada para velocidade e precisao. Campos de baixa confianca devem estar destacados visualmente. O raciocinio do agente deve estar acessivel para contexto. E acoes de aprovar/rejeitar/corrigir devem ser de um clique.

Batch review — revisar multiplos casos em sequencia com interface otimizada — e essencial para manter throughput. Metricas de tempo por revisao e taxa de concordancia entre revisores informam melhorias no design e na calibracao do sistema.

💡 Conceito Principal

Interface de revisao otimizada: highlight de campos incertos, raciocinio do agente visivel, one-click approve/reject, batch review. O design deve minimizar tempo de revisao sem sacrificar qualidade do feedback.

🎯 Elementos Essenciais da Interface

  • •Highlight visual de campos com score abaixo do threshold
  • •Raciocinio do agente expandivel para cada campo
  • •Dados-fonte originais acessiveis para comparacao
  • •Botoes de approve/reject/edit de acesso rapido
  • •Metricas de tempo e throughput de revisao por sessao
