🎯 Regras Condicionais por Caminho

📄 Frontmatter YAML paths

Arquivos em .claude/rules/ podem comecar com um bloco frontmatter YAML delimitado por ---. O campo mais importante e paths, que recebe uma lista de glob patterns definindo para quais arquivos a regra se aplica.

Quando Claude edita ou le um arquivo, o sistema verifica quais regras tem paths que correspondem ao caminho do arquivo. Apenas as regras com match sao injetadas no contexto. Regras sem frontmatter ou sem campo paths sao tratadas como globais e sempre carregadas.

💡 Conceito Principal

O frontmatter YAML com paths transforma regras estaticas em regras condicionais. Em vez de carregar todas as regras sempre, o sistema carrega apenas as relevantes para os arquivos sendo manipulados. Isso economiza tokens e mantém o contexto focado.

2

⚡ Carregamento Condicional

O mecanismo de carregamento condicional funciona assim: quando Claude comeca a trabalhar em um arquivo, o sistema verifica todos os arquivos em .claude/rules/ e faz match dos glob patterns no campo paths contra o caminho do arquivo ativo. Regras que fazem match sao adicionadas ao system prompt.

Isso e completamente automatico — nao requer nenhuma acao do usuario. Conforme Claude navega entre arquivos, as regras aplicaveis mudam dinamicamente. Editando um .test.ts? Regras de teste sao carregadas. Mudou para um .py? Regras de Python entram.

📊 Fluxo de Carregamento

1

Claude abre/edita um arquivo (ex: src/api/users.ts)

2

Sistema verifica paths de cada regra em .claude/rules/

3

Regras com match (ex: "src/api/**") sao injetadas no contexto

4

Regras sem match nao consomem tokens

3

🔍 Glob Patterns

Glob patterns sao a linguagem usada no campo paths para definir quais arquivos ativam a regra. Os padroes seguem a convencao padrao de glob: * corresponde a qualquer sequencia de caracteres em um unico nivel de diretorio, e ** corresponde recursivamente a qualquer profundidade de subdiretorios.

📝 Exemplos de Glob Patterns

*.ts Todos os arquivos .ts na raiz
**/*.ts Todos os .ts em qualquer profundidade
src/api/** Tudo dentro de src/api/ recursivamente
**/*.test.* Todos os arquivos de teste em qualquer linguagem
*.env* Arquivos de ambiente (.env, .env.local, etc.)
4

💰 Economia de Tokens

Em um projeto com 20 arquivos de regras em .claude/rules/, sem paths todas as 20 regras seriam carregadas em TODAS as sessoes, consumindo tokens desnecessarios. Com paths, se Claude esta editando um arquivo Python, apenas as 3-4 regras relevantes para Python sao carregadas. As outras 16-17 regras nao consomem nenhum token.

A economia e significativa: menos tokens no system prompt significa mais espaco para resultados de ferramentas, historico de conversa e raciocinio de Claude. Em projetos grandes com muitas regras, isso pode representar milhares de tokens economizados por sessao.

🎯 Impacto Pratico

  • •Custo: Menos tokens no prompt = menor custo por chamada de API
  • •Qualidade: Menos ruido no contexto = melhores decisoes de Claude
  • •Escala: Permite ter dezenas de regras sem impacto negativo
  • •Longevidade: Mais espaco para contexto de conversa em sessoes longas
5

🔧 Exemplos Praticos

Veja exemplos concretos de como organizar regras condicionais para diferentes dominios do projeto. Cada arquivo em .claude/rules/ foca em um topico especifico e usa paths para se ativar apenas quando relevante.

testing.md

paths: ["**/*.test.*", "**/*.spec.*"]

Regras para testes: usar describe/it, mocks isolados, cobertura de edge cases, assertions claras.

api-design.md

paths: ["src/api/**", "src/routes/**"]

Convencoes REST, validacao Zod, formato de erro RFC 7807, versionamento de endpoints.

security.md

paths: ["src/auth/**", "*.env*", "**/middleware/**"]

Regras de seguranca: nao expor segredos, validar input, sanitizar output, usar HTTPS.

database.md

paths: ["**/*.sql", "src/db/**", "**/migrations/**"]

Convencoes SQL: usar parametros preparados, indexacao, migrations reversiveis.

⚖️ Vantagens sobre CLAUDE.md por Diretorio

CLAUDE.md por diretorio (colocar CLAUDE.md em subdiretorios) e .claude/rules/ com paths sao abordagens complementares, mas .claude/rules/ oferece vantagens significativas para a maioria dos cenarios.

✅ .claude/rules/ com paths

  • •Centralizado: todas as regras em um lugar
  • •Flexivel: patterns podem cruzar diretorios
  • •Por tipo: filtrar por extensao, nao por local
  • •Manutencao: facil ver todas as regras do projeto

📁 CLAUDE.md por diretorio

  • •Distribuido: regras espalhadas pelo projeto
  • •Limitado: so se aplica ao diretorio local
  • •Por local: filtrar por diretorio, nao por tipo
  • •Manutencao: precisa navegar pelo projeto

📋 Resumo Final

✓Frontmatter YAML com paths define quando regras sao carregadas
✓Carregamento condicional acontece automaticamente baseado nos arquivos ativos
✓Glob patterns usam * (nivel) e ** (recursivo) para definir escopos
✓Economia significativa de tokens em projetos com muitas regras
✓.claude/rules/ com paths e preferivel a CLAUDE.md por diretorio na maioria dos casos
✓Regras sem paths sao globais — sempre carregadas
