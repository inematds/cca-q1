🔍 Grep vs Glob

Grep busca conteudo dentro de arquivos — procura por texto, expressoes regulares, padroes dentro do codigo. Glob busca arquivos por padrao de nome — encontra arquivos que correspondem a um padrao como *.ts ou src/**/*.test.js.

As duas ferramentas sao complementares: Glob encontra os arquivos certos, Grep encontra o conteudo certo dentro deles. Um padrao comum e usar Glob primeiro para filtrar os arquivos relevantes e depois Grep para localizar o codigo especifico dentro desses arquivos.

💡 Conceito Principal

Grep = busca por conteudo (o que esta DENTRO dos arquivos). Glob = busca por nome de arquivo (quais arquivos existem). Confundir os dois e um erro comum. Use Glob para encontrar os arquivos, Grep para encontrar o codigo.

🔍 Grep (Conteudo)

  • • "Encontre onde a funcao handleError e definida"
  • • "Quais arquivos importam o modulo auth?"
  • • "Onde esta a string TODO: fix?"
  • • Busca por regex dentro de arquivos

📁 Glob (Nomes)

  • • "Liste todos os arquivos .test.ts"
  • • "Quais arquivos existem em src/components/?"
  • • "Encontre todos os package.json"
  • • Busca por padrao de nome de arquivo

📝 Read/Write vs Edit

Read le o conteudo completo de um arquivo. Write sobrescreve um arquivo inteiro com novo conteudo. Edit faz modificacoes cirurgicas — substitui apenas um trecho especifico, preservando o resto do arquivo intacto.

Edit e preferivel para mudancas pontuais porque economiza tokens (envia apenas o diff, nao o arquivo inteiro) e preserva conteudo que nao precisa mudar. Write e necessario quando o arquivo inteiro precisa ser reescrito ou quando Edit falha por match ambiguo.

⚡ Dica Pratica

Regra geral: use Edit para mudancas pontuais (alterar uma funcao, corrigir um bug, adicionar um import). Use Write para criar arquivos novos ou reescrever arquivos inteiros. Use Read antes de Write para garantir que voce nao perde conteudo existente.

📍 Quando Usar Cada Ferramenta

R

Read

Inspecionar conteudo, entender estrutura, verificar estado atual. Sempre Read antes de Write para nao perder conteudo.

E

Edit

Mudancas pontuais: corrigir bug, alterar funcao, adicionar import. Economiza tokens e preserva conteudo nao-modificado.

W

Write

Criar arquivo novo ou reescrever inteiro. Fallback quando Edit falha. Sempre Read primeiro para preservar conteudo.

3

🔄 Fallback quando Edit Falha

Edit funciona substituindo um trecho exato de texto (old_string) por outro (new_string). Isso falha quando o old_string nao e unico no arquivo — ou seja, existe mais de um trecho identico e Edit nao sabe qual substituir. Isso e um "match ambiguo" e Edit recusa a operacao para evitar modificar o trecho errado.

Quando Edit falha, a estrategia de fallback correta e: (1) Read o arquivo completo para entender o contexto e identificar o trecho correto, (2) Write o arquivo inteiro com as modificacoes aplicadas. Esse padrao Edit → Read + Write e fundamental e extensivamente testado no exame CCA.

💡 Conceito Principal

Edit falha em match nao-unico (old_string aparece mais de uma vez). Fallback: Read completo → Write completo com as modificacoes aplicadas. Alternativa: fornecer mais contexto no old_string para tornar o match unico (incluir linhas adjacentes).

⚠️ Alerta

Nunca tente "forcar" Edit quando o match e ambiguo. Edit recusa a operacao por seguranca — se modificasse o trecho errado, poderia corromper o codigo. O fallback Read + Write e a abordagem segura e correta. Outra opcao e incluir mais linhas de contexto no old_string para desambiguar.

🧩 Entendimento Incremental

Claude Code nao le o codebase inteiro de uma vez. Ele constroi entendimento de forma incremental — comecando com buscas amplas para localizar pontos de entrada, depois lendo arquivos especificos, seguindo imports e dependencias, e expandindo o entendimento sob demanda. Cada passo informa o proximo.

Esse comportamento e por design: ler tudo de uma vez estouraria a janela de contexto e desperdicaria tokens com informacao irrelevante. O entendimento incremental e eficiente porque carrega apenas a informacao necessaria para a tarefa atual, no momento em que e necessaria.

📊 Fluxo de Entendimento Incremental

  • 1. Busca ampla: Grep para localizar padroes, funcoes ou termos relevantes no codebase.
  • 2. Leitura dirigida: Read nos arquivos identificados como relevantes pelo Grep.
  • 3. Seguir imports: identificar dependencias e ler os modulos importados.
  • 4. Expandir sob demanda: repetir o ciclo para areas que precisam de mais contexto.

⚡ Dica Pratica

Projete a estrutura do codebase para facilitar entendimento incremental: nomes de arquivo descritivos, imports claros, README no diretorio raiz, e convencoes consistentes. Isso permite que Claude Code navegue eficientemente e construa contexto com menos passos.

5

🔗 Trace de Funcoes

Trace de funcoes e a pratica de seguir o fluxo de execucao de uma funcao pelo codebase — de onde e chamada (chamadores), o que chama (dependencias), quais parametros recebe e retorna. Claude Code faz isso naturalmente usando a cadeia Grep → Read → Grep.

O trace bidirecional e particularmente util: dado uma funcao, encontrar todos os seus chamadores (quem a usa) E todas as suas dependencias (o que ela chama). Isso permite entender tanto o impacto de uma mudanca (quem e afetado) quanto os pre-requisitos (do que depende).

💡 Conceito Principal

Trace de funcoes: Grep para localizar a funcao → Read para entender a implementacao → Grep para encontrar chamadores. O trace bidirecional revela tanto o impacto de mudancas quanto as dependencias da funcao. Essencial para debugging e refatoracao.

✅ Fazer

  • • Grep para encontrar onde a funcao e definida
  • • Read para entender a implementacao completa
  • • Grep novamente para encontrar todos os chamadores
  • • Seguir imports para entender dependencias

❌ Evitar

  • • Ler o codebase inteiro para encontrar uma funcao
  • • Assumir o comportamento sem ler a implementacao
  • • Ignorar chamadores ao fazer refatoracao
  • • Modificar funcao sem entender quem depende dela
6

🔄 Cadeia Grep-Read-Imports

A cadeia Grep → Read → seguir imports e o padrao fundamental de exploracao de codebases no Claude Code. Grep localiza o ponto de entrada (funcao, classe, variavel), Read carrega o conteudo do arquivo para analise, e os imports no topo do arquivo revelam dependencias que podem precisar ser exploradas.

Este ciclo se repete ate que Claude tenha contexto suficiente para a tarefa. A chave e que cada iteracao e dirigida pela necessidade — Claude nao le arquivos "por curiosidade", mas porque o passo anterior revelou uma dependencia ou referencia que precisa ser entendida. Isso maximiza a eficiencia de tokens.

💡 Conceito Principal

O ciclo Grep → Read → imports → Grep constroi um grafo de dependencias sob demanda. Cada passo e dirigido pela necessidade do passo anterior. Isso e como Claude Code realmente opera — entender este padrao permite prever e otimizar seu comportamento.

📊 Exemplo Pratico

  • 1. Grep "handleError" → encontra em src/utils/errors.ts e src/api/handler.ts
  • 2. Read src/utils/errors.ts → ve a implementacao e os imports (import { Logger } from './logger')
  • 3. Read src/utils/logger.ts → entende como erros sao logados
  • 4. Grep "handleError" → encontra 12 chamadores em 8 arquivos → entende o impacto
