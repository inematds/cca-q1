🔧 Ferramenta Agent (ex-Task)

A ferramenta Agent (anteriormente chamada de Task, renomeada na versao v2.1.63) e o mecanismo principal para criar subagentes programaticamente. Quando um coordenador precisa delegar trabalho, ele invoca a ferramenta Agent para spawnar um subagente com instrucoes e contexto especificos.

💡 Conceito Principal

O Agent tool permite que um agente coordenador crie subagentes especializados. Cada subagente recebe seu proprio contexto, ferramentas permitidas e instrucoes. O coordenador espera o resultado e decide o proximo passo.

// O coordenador deve ter "Agent" em allowedTools
allowedTools: ["Agent", "Read", "Write"]
// Ao invocar Agent, o coordenador especifica:
- prompt: instrucoes para o subagente
- allowedTools: ferramentas que o subagente pode usar
2

🔑 allowedTools e Restricoes

Cada subagente pode ter acesso restrito a ferramentas via allowedTools no AgentDefinition. Isso impede que subagentes usem ferramentas fora de seu papel. Acesso com escopo = decisoes melhores.

💡 Conceito

Restringir ferramentas por subagente e uma pratica fundamental. Um agente de pesquisa nao precisa de Write. Um agente de escrita nao precisa de Bash. A regra de ouro e: 4-5 ferramentas por agente — menos opcoes levam a decisoes melhores.

✅ Fazer

  • • Restringir ferramentas ao minimo necessario por papel
  • • Agente de leitura: apenas Read, Grep, Glob
  • • Agente de escrita: Read + Write + Edit
  • • Manter 4-5 ferramentas por agente

❌ Evitar

  • • Dar acesso total a todas as ferramentas
  • • Subagente com Bash sem restricoes
  • • Misturar papeis: leitura + escrita + execucao
  • • Mais de 8 ferramentas em um unico agente
3

📦 Contexto Explicito

O contexto do subagente deve ser fornecido EXPLICITAMENTE — nao ha heranca automatica. Inclua descobertas previas completas nos prompts dos subagentes. Use formatos de dados estruturados para passagem de metadados.

⚠️ Alerta Critico

Nao ha heranca automatica de contexto! Um subagente nasce com uma conversa vazia. Se o coordenador descobriu que o arquivo principal e src/main.ts, ele deve incluir essa informacao explicitamente no prompt do subagente. Caso contrario, o subagente tera que redescobrir tudo do zero.

🎯 Dica Pratica

Estruture o prompt do subagente com todas as informacoes necessarias:

// Prompt para subagente — inclua contexto completo
"Voce esta trabalhando no projeto X.
Arquivos relevantes: src/main.ts, src/utils.ts
Descoberta previa: a funcao parseConfig tem um bug na linha 42.
Sua tarefa: corrigir o bug e adicionar testes."
4

⚙️ AgentDefinition Config

O AgentDefinition e como voce define a "personalidade" e as capacidades de cada subagente. Inclui descricoes, system prompts e restricoes de ferramentas. Essa configuracao determina o comportamento e os limites do subagente.

💡 Conceito Principal — Estrutura do AgentDefinition

{
"name": "code-reviewer",
"description": "Revisa codigo para bugs e padroes",
"systemPrompt": "Voce e um revisor de codigo experiente...",
"allowedTools": [
"Read", "Grep", "Glob"
],
"maxTurns": 10
}
  • name: identificador unico do agente
  • description: o que o agente faz (usado pelo coordenador)
  • systemPrompt: instrucoes de comportamento do agente
  • allowedTools: lista de ferramentas com acesso permitido
  • maxTurns: limite de turnos para evitar loops infinitos

🔀 fork_session

O fork_session permite explorar abordagens divergentes a partir de uma base compartilhada. Como branches do git — explore sem poluir a conversa principal. Util para comparar diferentes solucoes.

💡 Conceito Principal

fork_session cria uma copia da sessao atual em um ponto especifico, permitindo que o agente explore um caminho alternativo sem afetar o fluxo principal. Diferente do Agent tool (que cria um subagente novo), fork_session herda todo o contexto ate o ponto do fork.

// Analogia com git:
main ───●───●───●───●───● (conversa principal)
└──●──●──● (fork: abordagem A)
└──●──● (fork: abordagem B)

🎯 Dica Pratica

Use fork_session quando voce precisa testar hipoteses concorrentes. Por exemplo: "A solucao ideal e usar uma fila ou um banco de dados?" — faca fork para cada abordagem, avalie os resultados, e volte a conversa principal com a melhor solucao. O custo e minimo e o ganho de qualidade e significativo.

6

⚡ Subagentes Paralelos

E possivel spawnar subagentes paralelos em uma unica resposta do coordenador. Isso maximiza o throughput. O coordenador pode lancar multiplos subagentes simultaneamente e agregar resultados apos todos completarem.

💡 Conceito

Quando o coordenador faz multiplas chamadas ao Agent tool na mesma resposta, os subagentes sao executados em paralelo. Cada um resolve sua tarefa independentemente, e o coordenador recebe todos os resultados para sintetizar.

// Coordenador: uma resposta, 3 subagentes
Agent("Analise o frontend...") → subagente A
Agent("Analise o backend...") → subagente B
Agent("Analise o database...") → subagente C
// Todos rodam em paralelo → coordenador agrega

📊 Dados e Pesquisa

A execucao paralela de subagentes traz ganhos significativos de eficiencia:

3x
Mais rapido que serial
N:1
N subagentes, 1 coordenador
Isolado
Falha de um nao afeta outros
